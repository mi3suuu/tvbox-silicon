## 附：本表怎么机器校验（2026-11-06 第 7 轮补）

「落地文件」这一列**不是纯路径**，混了三种写法。直接拿路径去 `test -f` 会误报，所以要先按类型分开：

| 写法 | 例子 | 校验方式 |
|---|---|---|
| **完整路径** | `App/EpisodePicker.swift` | `test -f` 直接查 |
| **省略目录的裸文件名** | `Sources/TVCore/RemuxPlan.swift` | 按 basename 反查 `git ls-files`（36 处属于这类） |
| **符号名**（类型/方法/属性） | `Store.selectEpisode`、`showsEpisodes`、`SubscriptionEntry.environmentID` | `grep -rn` 计数 > 0 |

### 实测结果（第 7 轮）

```
条目 90 个
  完整路径直接命中
  裸文件名经 basename 反查全部命中（36 处）
  符号名经 grep 全部命中：
    showsEpisodes              20 次
    recoverLiveAfterDrop        5 次
    autoPlayNext               14 次
    SubscriptionEntry          42 次
    PlaybackView                在 App/RootView.swift
    resume                     125 次
真缺失：0
```

### 一条特例

`F-14 Duo 外屏横持白屏` 的落地列是 `—`，因为它是**修正**不是新增文件，实际改动在
`App/RootView.swift` 的 `tabSafeArea`（补 `else { self }`），commit `c62c49e`。
这类「已修」条目按 commit 核对，不按文件核对。

> **校验脚本的坑**：第一版只做了 `os.path.exists()`，报了 31 条「缺失」，全是裸文件名和符号名。
> 和 §十 记的那次一样 —— **判据没覆盖全部形态，就会批量误报**。
