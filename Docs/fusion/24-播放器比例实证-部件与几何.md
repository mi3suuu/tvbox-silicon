# 播放器比例：二进制结构 + 真机实测

## 一、比例的真实实现（`swift-section objc dump`）

### 1. 三层结构
```
BBPlayerRenderContainerWidget          ← 比例的唯一持有者
├── BBPlayerRenderVideoWidget          ← 画面层（约束切换）
└── BBPlayerRenderChronosWidget        ← 控件/进度层（独立 frame！）
```

### 2. 比例的四个独立维度（不是"一个 gravity"）
```objc
@interface BBPlayerRenderContainerWidget {
    double _ratio;                    // ① 比例数值
    long long _videoContentMode;      // ② 内容模式（决定 ratio 怎么算）
    long long _videoWidgetAlignMode;  // ③ 画面对齐
    long long _chronosWidgetAlignMode;// ④ 控件对齐（与 ③ 独立！）
    NSLayoutConstraint *_videoWidgetLeft/Right/Top/Bottom/HeightConstraint;
}
+ (long long)convertVideoContentMode:(long long)mode;
- (void)setViewRatio:(double)r;
- (void)adjustVideoConstraints:(double)r;     // ← 比例真正落地的地方
- (void)adaptVideoContentMode;
- (void)reloadRenderMode;
- (void)resetDefaultRenderMode;
```

### 3. 每形态独立配置
```objc
@interface BBPlayerRenderLayout {
    double halfScreenViewRatio;              // 半屏
    double fullScreenViewRatio;              // 全屏
    double portraitHalfScreenViewRatio;      // 竖屏半屏
    // 每个 ratio 配两个 AlignMode（video / chronos）
}
```

### 4. 五种模式靠**换约束**实现，不是缩放
```objc
@interface BBPlayerRenderVideoWidget {
    NSLayoutConstraint *_playerViewLeftConstraint;        // 普通四条
    NSLayoutConstraint *_playerViewRightConstraint;
    NSLayoutConstraint *_playerViewTopConstraint;
    NSLayoutConstraint *_playerViewBottomConstraint;
    NSLayoutConstraint *_playerViewLeftAspectConstraint;  // 四条 Aspect 变体
    NSLayoutConstraint *_playerViewRightAspectConstraint;
    NSLayoutConstraint *_playerViewTopAspectConstraint;
    NSLayoutConstraint *_playerViewBottomAspectConstraint;
    unsigned long long _activatedConstraintAttri;         // ← 切换哪一组
}
- (void)setContentMode:(long long)mode;
- (void)activateConstraints:(unsigned long long)attr;
```

## 二、我们的实现差距

| 维度 | 二进制 | 我们 | 判定 |
|---|---|---|---|
| 比例数值 | `double _ratio` 独立数据 | 无此概念 | ❌ |
| 内容模式 | `_videoContentMode` 决定 ratio 算法 | 用 `AVLayerVideoGravity` 三值硬套五模式 | ❌ |
| 画面对齐 | `_videoWidgetAlignMode` | 无 | ❌ |
| **控件对齐** | `_chronosWidgetAlignMode`（**独立**） | **无此概念** | ❌ |
| 实现方式 | 换 8 条约束之一 | gravity 拉伸 | ❌ 机制不同 |

**核心差距：哔哩哔哩是「比例是数据 + 约束切换」，我们是「gravity 拉伸」。**
控件层有**自己独立的 frame 与对齐**（`_chronosWidgetAlignMode`），
所以画面比例变化时**控件不跟着变** —— 我们完全没有这层。

## 三、真机实测（466×678 竖屏，片源 16:9）

```
video rect: x 0..1397  y 623..1409 (px)
          = 466.0 × 262.3 pt
aspect = 1.7764   （16:9 = 1.7778，差 0.0014）
画面 top = 207.7pt  bottom = 469.7pt
```

### 修复的 defect
`BiliMetrics.portraitHeight` 里：
```swift
static let portraitPlayerHeight: CGFloat = 250   // 写死
guard width >= 560 else { return portraitPlayerHeight }   // ← 466 < 560 恒命中
```
**Duo 外屏 466 宽永远返回写死的 250pt，完全不看片源比例。**

实测画面 262.3pt，容器 250pt → **错位 12.3pt**（底栏压在画面上、进度条偏移）。
已删短路，改为 `width / ratio`：
```
466 ÷ 1.7778 = 262.12 pt  ← 与实测 262.3 差 0.18pt
```

## 五、本轮修复的三个真缺陷

### 5.1 `fixedAspect` 定义了却无人使用
```swift
var fixedAspect: CGFloat? { case .ratio16x9: 16/9; case .ratio4x3: 4/3; default: nil }
```
grep 全仓库：**只有定义，0 个使用点**。
后果：用户选「16:9」「4:3」时容器尺寸不动，看起来什么都没发生。

已新增 `BiliAspectMode.effectiveAspect(sourceRatio:mode:)`，
三个调用点（2608 / 2636 / 2731）统一走它。

### 5.2 `adjustScreen` 与 `centerCrop` 的 gravity 完全相同
```swift
// 旧
case .adjustScreen: return .resizeAspectFill
case .centerCrop:   return .resizeAspectFill   // ← 与上一行一模一样
```
二进制里它们是 `_videoContentMode` 的**两个不同枚举值**
（`playersetting_ratioadjustscreen` / `ratiocentercrop`），不可能行为相同。

已拆分：
```
adjustScreen → .resize            铺满（可能变形）
centerCrop   → .resizeAspectFill  等比裁切
```

### 5.3 `portraitHeight` 的 width 短路
见上文第三节，已删 `guard width >= 560`。

## 六、仍未实现的一层：控件独立对齐

### 实测现状（全屏竖屏 466×678，16:9 片源）
```
画面    y 207.7 .. 469.7   高 262.0
上方黑边 208.0   下方黑边 208.0   → 垂直居中 ✓
控制栏  时间 507.0 / 播放 516.0 / 弹幕 610.0 / 画质 619.7
        → 全部落在画面【下方黑区】46~150pt
```

**画面本身是对的**（宽铺满、16:9、垂直居中），
但控件贴在屏幕底部，不是贴在画面内。

### 二进制里这正是 `_chronosWidgetAlignMode` 管的
```objc
double _ratio;
long long _videoWidgetAlignMode;     // 画面对齐
long long _chronosWidgetAlignMode;   // 控件对齐 ← 与上面独立
BBPlayerRenderChronosWidget 持三套独立 frame：
  - updateVideoFrame:     画面
  - updateVisibleFrame:   可见区（含遮挡避让）
  - updateSubtitlesFrame: 字幕
```

我们没有这一维：控件只按屏幕贴边，没有「贴画面」的概念。

B 站实际行为（待真机对照原版确认）：全屏时控件是**贴屏幕底**的
（因为全屏时画面铺满整屏，两者等价）；但**半屏**时画面只占上半，
控件应贴**画面下沿**而不是屏幕底 —— 这才是 `chronosWidgetAlignMode` 存在的意义。
