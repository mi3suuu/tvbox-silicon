`ui.tree` 带 `frame`（x/y/width/height），比 OCR 精确。连续多次读取结果稳定：

```
  0.0  24.0   54.0 × 44.0    'Back'   bbplayer_fullscreen_back
 54.0  24.0  632.0 × 44.0    'BLG defeated T1, Doran went to Bin…'   标题

 16.0  92.0  134.0 × 26.0    '发现《我们俩》'                 音乐标签
```

### 顶栏版式的三条硬结论

1. **返回键 54×44pt**（不是常见的 44×44），且 `x=0` —— 贴左物理边缘，无 left inset。
2. **标题从 x=54 开始、宽 632** —— 即标题**紧贴返回键右侧**，一直铺到屏幕右缘
   （54+632 = 686 ≈ 678 屏宽，略溢出说明标题允许贴近边沿）。
   **标题是左对齐紧跟返回键，不是居中、不是右对齐。**
3. 顶栏整体高度 **24→68pt = 44pt**，与返回键高一致。

### 关于底栏：结构性结论

连续 6 次读取 `ui.tree`，元素数在 `0` 与 `5` 之间跳变：

```
run 5 → 0 → 5 → 5 → 0 → 5
```

变化只发生在「控件显示 / 自动隐藏」之间，**始终是同一批 5 个元素**。
结论：**哔哩哔哩全屏底栏没有为任何控件设置 accessibility**，
所以结构树里永远拿不到进度条、播放键、Subtitles/Speed/Auto。
底栏数据只能来自像素（第 12 节已取到）。

这同时解释了一个此前的疑问：为什么 `visible_only:false` 返回 0 而不是补全——
该参数在控件隐藏时拿到的是空树，不是「包含隐藏元素」的树。

## 14. 三态的真实组件结构（类名证据，纠正第 12 节「全屏无选集入口」的误判）

### 先撤回一个错误结论

第 12 节我写过「**全屏态不提供选集入口**」——**这是错的**，是我从像素没找到就推定不存在。
类名证据直接推翻：

```
BBPlayerFullScreenEpisodeBtnWidget       ← 全屏的选集按钮
BBPlayerFullScreenCoinBtnWidget          ← 全屏的投币按钮
BBPlayerFullScreenShareBtnWidget         ← 全屏的分享按钮
BBHD2MPFullScreenEpisodeBtnWidget
BBPgcFullScreenEpisodeBtnWidget          ← PGC（番剧）版
BBPgcFullScreenNextEpisodeBtnWidget      ← 下一集
```

全屏**有**选集入口，只是没有 accessibility，像素扫描也没覆盖到它的位置。

### 三态 = 三个独立的 Widget 族，每族四个区

```
全屏  BBPlayerFullScreen{Top,Bottom,Left,Right}Widget
      + FullScreenEpisodeBtn / CoinBtn / ShareBtn / EndPage
      + FullScreenState

半屏  BBPlayerHalfScreen{Top,Bottom,Left,Right}Widget
      + HalfScreenBottomRowLayout      ← 底栏是「行布局」
      + HalfScreenEndPage / EndPageReplay
      + HalfScreenVerticalSpacerLine

竖屏  BBPlayerPortraitScreen{Top,Bottom}Widget   ← 只有上下，没有左右
      + PortraitScreenEndPage
```

结构性结论：

| 观察 | 含义 |
|---|---|
| 每态都有独立的 Top/Bottom/Left/Right | 三态**不是同一套布局换参数**，是三套代码 |
| 只有半屏有 `BottomRowLayout` | 半屏底栏按「行」排；全屏底栏不是 |
| 竖屏缺 Left/Right | 竖屏没有侧栏概念 |
| 全屏缺 `RowLayout`、但有 4 个独立按钮 Widget | 全屏按钮**各自定位**，不排成一行 |

这解释了为什么我此前把「播放器里的更多」和「选集」放在同一页是错的 ——
它们分属不同 Widget，甚至不同屏幕族。

### 选集功能的完整实现链

```
数据    BBPlayerEpisodeConfig
        BBPlayerCommonSwift.BBPlayerEpisodeList
        EpisodeListBageInfo / BBPlayerBizAnyEpisodeList

入口    FullScreenEpisodeBtnWidget   （全屏）
        HalfScreen 的选集入口          （半屏详情页）
        BBPgcFullScreenNextEpisodeBtnWidget（番剧下一集）

面板    BBPlayerEpisodeListWidget + ListHeaderView + ListCollectionCell
        ListStyle / ListType / ListSegment 三个枚举
        BBPgcEpisodeListSheetVC + SheetCell + SheetHeaderView + SheetSectionVM
          （番剧走 Sheet 路线，与 UGC 的 Widget 路线不同）

小窗    BBMiniScreenEpisodeList / BBHD2MPMiniScreenEpisodeList
        BBHD2MPPiPEpisodeListBloc（画中画）
```

**结论：选集入口在每个屏幕族都有一份，且 UGC 走 Widget、PGC 走 SheetVC 两条不同实现。**
