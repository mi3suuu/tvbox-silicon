## 一、三条不可违反的铁律

1. **上游文件是「别人的文件」。** 除 M1–M8 已登记的必要侵入点外，一律不在上游文件里写二开逻辑。
   - 新增能力 → 新建文件（`App/…` 或 `Sources/TVCore/…`）。
   - 给上游类型加**方法/计算属性** → `extension`，写在独立文件里（命名 `Xxx+Mi3s.swift`）。
   - 给上游类型加**存储属性** → 无法 extension（Swift 限制），必须侵入主类；侵入处**必须**写
     `// [mi3s] 二开：<原因>` 单行标记，并登记到 `03-侵入点登记表.md`。
2. **`TVBox.xcodeproj/project.pbxproj` 绝不手改。** 只用 `xcodegen generate --spec project.yml` 重新生成。
3. **不删上游已有实现。** 上游已等价实现的，我方版本直接丢弃并记入 `02-未纳入清单.md`。

## 五、编译与验收命令（唯一口径）

```bash
# TVCore 单测（最快，先跑这个）
swift test --package-path Packages/TVCore 2>&1 | tail -30

# 三平台编译（缺一不可）
xcodegen generate --spec project.yml
xcodebuild -project TVBox.xcodeproj -scheme TVBox-macOS -configuration Debug -derivedDataPath build/DD-mac build
xcodebuild -project TVBox.xcodeproj -scheme TVBox-iOS   -configuration Debug -derivedDataPath build/DD-ios -destination 'generic/platform=iOS' build
xcodebuild -project TVBox.xcodeproj -scheme TVBox-tvOS  -configuration Debug -derivedDataPath build/DD-tvos -destination 'generic/platform=tvOS' build
```

> iOS/tvOS 需要 `build/AppleRuntime/<platform>/`（JVM/Python/Node 宿主）。若缺失，先跑
> `Scripts/build-universal-hosts.sh`，或只对 macOS 做编译门禁、把 iOS/tvOS 标为「待真机验收」。

## 六、四类改动的裁决口径（P10 专项结论）

| 类 | 内容 | 手段 |
|---|---|---|
| A | 纯新增能力 | 独立文件 ✅ |
| B | 给上游类型加方法/计算属性 | `extension` 独立文件 ✅ |
| C | 给上游类型加存储属性 | 装箱成 `@Observable` 状态箱，主类只留 1 行引用 ⚠️ |
| D | 改上游已有逻辑 | 尽量用组合/协议绕过；绕不过才改原文件，必须 `[mi3s]` 标记 + 登记 ⚠️⚠️ |

## 七、判断「接不接」的三条判据

**丢弃（任一命中即丢）：**
1. 上游 1.8.11 已有等价实现；
2. 上游在分叉后新写了我方也写过的同名能力，且上游更完整；
3. 属旧架构，上游已用云化/数据驱动取代。

**保留（任一命中即留）：**
1. 上游无等价；
2. 属 iPhone Duo 折叠屏专属（上游不针对折叠设备）；
3. 属隐私保险库 / 备份 / 环境隔离等我方核心护城河。
