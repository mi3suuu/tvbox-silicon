## 二、为什么之前一定调不对（结构性原因）

**时间(507.0) 与 播放(516.0) 只差 8.9pt，而时间字高就有 13.3pt。**

这两个元素在垂直上**互相重叠**。任何 `VStack` 串行布局的最小间距 = 前一元素高度
= 13.3pt > 8.9pt → **串行排永远做不到**。

前一版算出播放落在 534.85（差 19pt），正是这个行的 13.3 + 居中差 14.85 叠加的结果。

**结论：底栏必须绝对定位，`VStack` + spacing/padding 无论怎么调都不可能对。**

## 四、review 中查出的 5 个真缺陷

### 1. 死代码 `chrome` 占着 `safeAreaPadding`（严重）
`body` 早改成 `Color.clear` + 四个 overlay，但 `chrome` 属性还在（50 行），
`.safeAreaPadding(.top)` 挂在它上面 → **从未执行** → 四项 overlay 无顶部安全区。
已删 `chrome`，偏移改为固定 **9.5pt**：
```
实测 Back 字形 y=24，44 热区、字形 15 居中 → 元素 top = 24 − (44−15)/2 = 9.5
（safeAreaPadding 在 Duo 外屏实测加 16.2pt，会偏高 14.5pt）
```

### 2. `bottomBar` 的 padding 调不动 → 必须固定高 + 内部偏移
`.padding(.bottom, N)` 每改一次，四个元素整体平移，永远只能对上 1~2 个。
改成 `frame(height: 200)` + 内部绝对 offset。

### 3. 横屏 offset 差 5pt
```
横屏 466 高，底栏 200 → 顶 y = 266
实测字形 407.7 − 14.85 = 392.85 → offset = 392.85 − 266 = 126.85
（我写了 132）
```

### 4. 四键重复渲染
`fullscreenPopupRows` 顶部已有 `heroButton` 四个大按钮
（See Original / Watch Later / PiP / Cast），我又在 `playSettingSection(.operation)`
里加了一遍同样四个 chip → **两套 UI**。已改为 `EmptyView()`。

### 5. `switch biliSettingsFocus` 与 5 个 Cell 重复渲染（最严重）
`ForEach(BiliPlaySettingSection.allCases)` 已渲染 Speed/PlaybackMode/Aspect/Options，
`switch` 里又渲染一遍 → **7 档倍速渲染 2 遍**（实测计数验证）。

二进制裁决：`PlaySettingWidget` 的五个 Cell 是**并列同时显示**的成员，
不是「切一下换一屏」的 page。`biliSettingsFocus` 唯一语义是**打开时滚到哪**。

已删 `.speed` / `.aspect` / `.colorFilter` 三个重复 case，
保留 `.quality`（Cell 里确无）、`.subtitles`、`.episodes`、`.menuEditor`、`.timer`。
