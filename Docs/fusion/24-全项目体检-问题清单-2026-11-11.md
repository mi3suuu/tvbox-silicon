## 一、已修（本轮落地，可复核）

### 1. `App/BiliMetrics.swift` — import 被关进 `#if os(iOS)`，尾段在 tvOS/macOS 无任何导入

**问题。** 本文件是**混合文件**：上半段（`BiliMetrics` / `BiliSettingsFocus`）只在 iOS 存在，
下半段（`BiliDanmakuSpeed` / `BiliDanmakuFilter`）被**跨平台**的 `App/DanmakuView.swift`
（守卫是 `!os(tvOS)`，即 macOS 也编译）使用。但三个 `import` 全写在 `#if os(iOS)` 里面。

**后果。** tvOS 上 24 个错误全部是 `cannot find type 'CGFloat' / 'CIFilter' / 'CIVector' /
'AVLayerVideoGravity' / 'UserDefaults'`，逐条都是「没有 import」而非「代码写错」。

**修法。** `import` 提升到守卫外（SwiftUI / AVFoundation / CoreImage / TVCore），
`import UIKit` 之类平台专属的留在守卫内。**没有动任何类型定义，没有移动 `#endif`**。

**为什么不能像直觉那样把 `#endif` 挪到文件末尾。** 第一版就是这么改的，结果
`DanmakuView.swift:84/160` 立刻报 `cannot find 'BiliDanmakuFilter' / 'BiliDanmakuSpeed'`
—— 因为那两个枚举必须**在守卫外**。已回退并按 import 修正。

### 2. `App/BiliPanels.swift` — `#endif` 提前 122 行闭合，尾部 `BiliFullscreenPopup` 在 tvOS 也编译

`#endif` 原本在第 944 行，但文件有 1066 行，尾部 91 行有效代码（`BiliFullscreenPopup`
+ `BiliPopupRow`）落在守卫外。该类型用 `BiliPalette`（iOS-only）、`UIApplication.appScreenBounds`。
把 `#endif` 移到文件末尾。

### 3. `App/RootView.swift` — 二开新增的播放退场裁决整块没有平台守卫

`PlaybackExitArbiter` + `onGeometryChange` 版式判定块（212 行，2026-11-10 新增）写在
`#if os(macOS) … #else … #endif` 的 `#else` 分支里 —— 那个分支**同时覆盖 iOS 与 tvOS**，
而两块代码都依赖 `PictureInPicture`（`App/MobilePlayer.swift` 内 `#if os(iOS)`）。

修：块本身包 `#if os(iOS)`；`PlaybackExitArbiter` 整个 struct 包 `#if os(iOS)`。

**顺带删掉一处死声明。** `PlayerPresentation` 里的
`@Environment(\.scenePhase) private var scenePhase` 在该 struct 内**一次都没被读**
（真正读它的是下面的 `PlaybackExitArbiter`，它有自己的那份）。留着会让人误以为
`PlayerPresentation` 参与场景判断。

### 4. `App/CatalogPlaybackActions.swift` — `PlainChromeButtonStyle` 落在 `#endif` 之后

该 ButtonStyle 只被本文件的（iOS/ macOS 用的）菜单引用，但写在 `#if !os(tvOS)` 之外，
tvOS 上 `View` / `ButtonStyle` / `Configuration` 全部找不到。包进 `#if !os(tvOS)`。

### 5. `App/OneSkinBackdrop.swift` — 文件级完全无守卫（**macOS 的第一道墙**）

整个文件围绕 `UIImage` / `UIViewRepresentable` / AVPlayerLayer 宿主 UIView 写。
macOS target 的第一个错误永远是 `OneSkinBackdrop.swift: import UIKit`。

**但不能整体加守卫。** 文件尾部的 `ScreenBackdropIfNeeded` 不碰 UIKit，被跨平台的
`VideoDetailView.swift:324` 使用。按「共享部分留外面」拆：
`import SwiftUI/TVCore` 提到守卫外，`import UIKit` 与全部 UIKit 类型进 `#if os(iOS)`，
`ScreenBackdropIfNeeded` 留在守卫外。

**实测验证：** macOS 构建的下一个错误已经不是这个文件，说明这道墙真的拆掉了。

### 6. `App/QALaunch.swift` + `App/SourceSpeedLab.swift` — 两处单行守卫写错

- `QALaunch` 里 `PlaySkin.bilibili` 的写入没有守卫，而 `PlaySkin` 定义在
  `BiliSkin.swift` 的 `#if os(iOS)` 内 → tvOS / macOS 的 QA 包编译失败。包 `#if os(iOS)`。
- `SourceSpeedLab` 里 `.navigationBarTitleDisplayMode(.inline)` 的守卫写的是
  `#if !os(tvOS)` —— 这是 **UIKit 侧 API，macOS 也没有**。改成 `#if os(iOS)`。
  这一行是 macOS 构建当时**唯一剩下**的错误。

**为什么本轮不动它们：**

1. **正在被并行会话写。** 体检期间实测到 `App/VideoDetailView.swift`、`App/BiliMetrics.swift`
   在 03:05:39 / 03:05:42 / 03:09:44 / 03:09:56 被连续修改，同一时刻
   `.dsh/memory` 里出现了新交接账本（03:17）。在这种状态下改同两个文件，改动会互相覆盖。
2. **正确解法是「拆层」不是「补守卫」。** `VideoDetailView` 要把哔哩哔哩皮肤与 One 皮肤
   的状态/方法整体搬进 `#if os(iOS)` 扩展；`OneSkin.swift` 要把跨平台消费的
   `OneSkinLineSample`（以及 `OneSkin.fitModeKey`、`OneSkin.enabledKey` 两个键常量）
   下沉到 `TVCore`，才能整文件加守卫。这是**结构性重构**，不是一行改动。
3. **这个项目有过教训**：铁律记着「OneSkin 三文件缺守卫时，修了这一处会暴露 17 处连带错误」
   —— 分批盲修会越修越乱。

**建议的处置顺序（供你选）：**
1. 先把 `OneSkinLineSample` / 两个 `UserDefaults` 键常量下沉 `TVCore`，`OneSkin.swift` 整文件加守卫；
2. `SettingsPlayback.swift` 里对 `PlaySkin` / `OneSkin` 的引用改为读下沉后的键；
3. `VideoDetailView` 的哔哩哔哩/One 成员搬进 `#if os(iOS)` extension；
4. 最后清 `SitesView` 的 `#if os(tvOS) extension`（它引用的 private 成员属于第 3 步）。
