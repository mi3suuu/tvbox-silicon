## 4. 逻辑级问题（编译过了也错）

### 4.1 🔴 `WatchNowPhone.swift` 泄漏保险库内容（iPhone 首屏）

```swift
// App/WatchNowPhone.swift
L20: return Array(store.visibleHistory.filter { … }.prefix(5))     ← 这一行是对的
L75: if sections.contains(.continueWatching), !store.playbackHistory.entries.isEmpty {
L77:     ForEach(store.playbackHistory.entries.prefix(12))         ← 裸数据
L99: if sections.contains(.favorites), !store.favorites.items.isEmpty {
L101:    ForEach(Array(store.favorites.items.prefix(20)))           ← 裸数据
```

同一个文件里 L20 走 `visibleHistory`、L75/77/99/101 走裸 `playbackHistory.entries` / `favorites.items`。

**危害**：保险库锁定期间，被藏源的**标题、封面缩略图**会画在 iPhone 首屏「继续观看」「收藏」两条轨上。这与保险库的设计目标（藏源整体消失）直接冲突，也与 `MoreView` 角标已改成 `visibleHistory.count` 的做法不一致（用户会看到「角标 0，但首屏有卡片」）。

**「首屏不算泄漏」不成立**：`WatchNowTV.swift:61-64` 那段注释明确写了「上游 `WatchNowTVPage` 直读裸数据…保险库锁定期间这两条轨会把被藏源的条目连同缩略图一起画在 Apple TV 首屏上。同机 iOS 走 `WatchNowPhone` 已是可见性出口」——**这句话现在是假的**，iOS 侧漏了。

**修法**（与 TV 侧对齐）：

```swift
L75: if sections.contains(.continueWatching), !store.visibleHistory.isEmpty {
L77:     ForEach(store.visibleHistory.prefix(12)) { HistoryCard(entry: $0) }
L99: if sections.contains(.favorites), !store.visibleFavorites.isEmpty {
L101:    ForEach(Array(store.visibleFavorites.prefix(20))) { WatchNowPhoneFavorite(item: $0) }
```

## 5. 本地化

### 5.1 `zh-Hans` 多出 72 个 en 表没有的 key

`Sources/TVCore/Resources/zh-Hans.lproj/Localizable.strings` 比 `en.lproj` 多 72 条（`Show`/`Move`/`Measured`/`Source Speed Test`/`Measure and file`/`%lld sources in scope`/`Probe This Group`…）；`zh-Hant` 和 `ja` **都没有这 72 条**。

后果：这 72 条只中文能翻到，繁中/日文/英文界面会 fallback 到 key 原文。

`Scripts/check-localizations.py` 因此直接断在第二行：

```
AssertionError: Mismatched keys: zh-Hans
```

**修法**：要么给 en/zh-Hant/ja 补这 72 条，要么从 zh-Hans 删掉（若对应界面已删）。

### 5.2 255 个 `L10n.text` 字面量不在 en 表里

| 归属 | 数量 |
|---|---|
| 二开新增文件 | 231 |
| 上游文件（被我们改过） | 40 |


`L10n.text` 实现（`Localization.swift:69`）是 `localizedString(forKey: key, value: key, …)` —— 找不到就用 key 当值。所以这些界面**在四种语言下都显示英文 key 原文**（例如 `"Show"` 显示成 `Show` 而非 `显示`），功能正常但语言不统一。

**修法**：`Scripts/check-localizations.py` 目前只检查「表里已有的 key」的一致性，**不检查「代码用了但表里没有」**。建议给它加一段反向检查，然后按 Top 文件补表。
