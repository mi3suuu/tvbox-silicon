## 二、增量刷新

`App/Store.swift`

```swift
var probeMaxAge: TimeInterval      // 默认 600 秒；0 = 从不跳过
private(set) var probeSkipped: Int?  // 上次因为读数较新而跳过的数量

private func needsProbing(_ sourceKey: String, maxAge: TimeInterval) -> Bool {
    guard maxAge > 0 else { return true }
    guard let reading = SourceProbeStore.shared.latest(sourceKey: sourceKey) else { return true }
    return reading.measuredAt.timeIntervalSinceNow < -maxAge
}
```

`probeTargets(_:skippingFresh:)` 在收集目标时就过滤，并记下跳过数；`startProbing(_:skippingFresh:)` 对单组同样处理。

**为什么用时间窗而不是"只测没测过的"**：一个三小时前测通、现在挂掉的源，如果永远跳过就再也不会被重新发现。时间窗让第二次点击几乎零成本，同时保证陈旧读数会被更新。

## 四、批量动词（`App/Store+SourceGrouping.swift`）

```swift
func answered(_ sites: [Site]) -> [Site]    // 读数说它通了
func silent(_ sites: [Site]) -> [Site]      // 读数说它不通
func unmeasured(_ sites: [Site]) -> [Site]  // 没有读数
func setRoute(_ route: SourceRoute, for sites: [Site]) -> Int
func routeByReachability(_ sites: [Site]) -> (direct: Int, relay: Int, unknown: Int)
```

**三类而不是两类**：`unmeasured` 单独存在，因为"没测过"不是"通"，也不是"不通"。把未测的源按"不通"路由等于把猜测写成设置，而用户不会回头复查。

## 五、面板（`App/SourceSpeedLab.swift`，303 行）

六个 Section：

| Section | 内容 |
|---|---|
| **Scope** | 全部源 / 单分组；跳过时间窗（从不 / 5 / 10 / 30 分钟 / 1 小时） |
| **Sweep** | 进度条 + 停止；按钮文案随 scope 变；"跳过 N 个：刚刚测过"；"待测 X 个，跳过 Y 个（读数较新）" |
| **Readings** | 源数 / 可达 / 不通 / 未测 / 最新读数时间 |
| **Grouping** | 可达建新组、不通建新组、**批量移入已有组**（菜单里每个组两个动作）、新建组 |
| **Routing** | 一键「可达→直连，不通→代理」，回报 N 直连 / M 代理 / K 未测保持 |
| **Forget** | 清除全部读数 |

深链接：`-qaSection sites -qaPage speed-lab`。
