# 出站代理 + Loon：两段端口，域名规则优先

2026-11-11 · 实测结论（已推翻早前结论）

## 一句话

Loon 里贴两行，**必须放在 `[Rule]` 最顶上**：

```
SRC-PORT,41500-41599,Proxy
SRC-PORT,41600-41699,DIRECT
```

- App 决定某源走代理 → 从 `4150x` 发起连接 → 走 Loon 当前选中线路
- App 决定某源直连 → 从 `4160x` 发起连接 → 直连

规则条数恒为 2，**与订阅数量无关**：它匹配源端口，不看域名。以后新增订阅、换节点、Loon 更新远程规则集都不用再动。

## 生效范围（实测，这是全部要点）

| 目标 | `SRC-PORT` 能否决定 |
|---|---|
| 裸 IP（无域名规则可匹配） | ✅ **能** |
| 域名，且**不在**你的分流规则里 | ✅ **能**（影视源的绝大多数） |
| 域名，**已在**分流规则里（如 linearmouse、snssdk、gemini） | ❌ **不能**，域名规则先行 |

第三行是 Loon 的既定顺序：**域名规则 → IP 规则 → 其他**（`SRC-PORT` 属"其他"）。所以被你自己规则分类过的站点，App 改不动它——这不是 bug，是 Loon 的设计。

## 决定性实测数据

**用裸 IP 做目标**（`DOMAIN-*` 无法匹配，`SRC-PORT` 才有机会表态）：

| 目标 | 拨号端口段 | 出口 | 说明 |
|---|---|---|---|
| 境外 IP `104.26.13.205` | 42601 范围外 | `45.207.157.52` | 走节点 |
| 境外 IP `104.26.13.205` | **41696 DIRECT 段** | **超时 0 字节** | **改直连被墙 ← 规则生效** |
| 境外 IP `104.26.13.205` | 41596 Proxy 段 | `45.207.157.52` | 走节点 |
| 国内 IP `118.184.169.32` | 41690 DIRECT 段 | `112.47.166.102` | 直连成功 |
| 国内 IP `118.184.169.32` | 41590 Proxy 段 | 超时 | 改走节点 |

四格交叉全部符合预期。

**用域名做目标**（`linearmouse.app`，配置里规则=节点选择）：

| 端口段 | 结果 |
|---|---|
| 42600 范围外 | 301 |
| 41695 DIRECT 段 | 301（**没有**变直连） |
| 41595 Proxy 段 | 301 |

三组完全相同 → **域名规则压在 `SRC-PORT` 之上**。

## 早前四轮结论为什么错了（教训）

早前判定"LAN 代理口上 `SRC-PORT` 无效"，四次实验拨的都是**域名**。域名规则先命中，把端口差异完全掩盖，于是三种端口出口一致 —— 那是**假阴性**。

**方法论**：判断某类规则是否生效，必须选该类规则**无法命中**的目标做控制变量。用域名测 IP/端口类规则，必然得出"无效"的错误结论。

同一批实验里还排除了一个环境干扰：本机 Clash 曾同时运行（TUN `utun4`/`198.18.0.1`）。经查 `route -n get 192.168.124.55 → en0` 且 TUN 网段不含 `192.168/16`，Clash 不在链路上；停掉 Clash 后复测结论一致，确认不是它造成的。

## App 侧落点

| 文件 | 内容 |
|---|---|
| `Sources/TVCore/SRCPortPool.swift` | 双 lane 端口池（借还/防重复）、规则片段、位置诊断、旧宽范围识别、**生效性自检类型** |
| `Sources/TVCore/LocalProxyServer.swift` | 代理连接走 proxy lane、直连走 direct lane；失败/取消归还；lane 空时记日志 |
| `Sources/TVCore/LoonPreset.swift` | 读实时配置，报告规则位置/缺直连行/旧宽范围，并在 caveat 里写明"域名规则优先"这一真实边界 |
| `App/CustomProxySettings.swift` | 「复制 Loon 规则」+ 两段端口显示 + 实时状态 + **「检查是否生效」自检** |

### 自检怎么判

同一裸 IP，从 Proxy 段与 Direct 段各拨一次：

- 两次结果**不同** → `effective`，规则在参与决策
- 两次结果**相同** → `overridden`，被更早的规则接管
- 两次都连不上 → `inconclusive`，不能诬告规则失效

必须用裸 IP，否则测到的只是域名规则的优先级。
