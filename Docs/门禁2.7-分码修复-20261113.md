# peer-gate 分码修复（第 1 项）

日期：2026-11-13 · 执行：纪律质检员 · 文件：`dsh-toolkit/bin/peer-gate`

## 问题

`peer-gate` 的 strict 档把 `peer-probe` 的 RC=3（未登记）压成 exit 1，
与 RC=1（真冲突）**同码同文案**，调用方无法区分两种完全不同的处置：

- 冲突 → 避重 / 开分支 / 第三方评审
- 未登记 → 把文件写进 `PEERS.md` 即可继续

## 改法

`3)` 分支在 strict 下改为 `exit 3`（不再 `exit 1`），并给未登记专属文案：

```
✘ peer-gate(strict): 【未登记，非冲突】目标不在任何路段的 claimed 里
   → 处置：把你要改的文件写进 PEERS.md 本路段 claimed，然后重跑；不需要避重。
   → 若这是不归任何路段的公共文件，用：PEER_GATE_STRICT=loose ...
```

契约注释同步改写为四态（0/1/2/3），并写明「strict 下 3 与 1 最终都让门禁变红，
但语义与文案必须分开」。

## 实测（改动前 → 改动后）

| 场景 | 改动前 RC | 改动后 RC | 期望 |
|---|---|---|---|
| 表新鲜·无目标 | 0 | 0 | 0 ✔ |
| 真冲突（`App/QALaunch.swift` 被路 B 占） | 1 | **1** | 1 ✔ |
| 未登记（strict） | 1 ← 混码 | **3** | 3 ✔ |
| 未登记（loose） | 0 | 0 | 0 ✔ |
| 环境错（`PEERS.md` 不存在） | 2 | **2** | 2 ✔ |
| 表不可解析（写入垃圾内容） | — | **1** | 1（表失效）✔ |

## 一个不是缺陷的现象（记录以免后人误判）

`peer-gate --bad-arg` 返回 **3**，不是 2。**这是正确行为**：`peer-probe` 把
所有位置参数一律当文件路径，`--bad-arg` 就是一个「未登记的目标」，返回 3 符合契约。
我一度误判为自己引入的语义错误，实测 `peer-probe --bad-arg` 自身也返回 3 后排除。

## 副作用检查

`PEERS.md` 跑完门禁后 md5 变化（`5aa9cdb0…` → `cc710fce…`），
`diff` 确认**仅 `last_seen` 时间戳不同**，其余零差异 —— 属门禁 2.7 自动刷新的正常行为，非损坏。
