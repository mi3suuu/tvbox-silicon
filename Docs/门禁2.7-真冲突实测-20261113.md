# 门禁 2.7 真冲突判红实测 —— 发现两个缺陷

日期：2026-11-13 · 执行：纪律质检员 · 环境：tvbox-silicon-fusion 主树（19 项未提交）

## 一、为什么要测

此前所有会话（含我自己）只验证了「表过期 → 判红」这一条。
**真冲突（另一路声明了本路文件）从未实测**，而门禁 2.7 存在的唯一理由就是抓这个。

## 二、实测方法

1. 备份 `PEERS.md`（md5 `65b7928218511401e5c80145a3ccd46b`）
2. 注入真冲突：把本路已声明的 `UITests/DuoAcceptanceUITests.swift` 加进路 B 的 `claimed`
3. 同时刷新路 B 的 `last_seen` —— **隔离变量**，排除「过期判红」的干扰
4. 分别用 strict 档跑「不传文件」与「传文件」

## 三、缺陷 1：gate.sh 不传文件 ⇒ 真冲突被静默放行（严重）

```bash
# tools/qa/gate.sh:284
PEER_GATE_STRICT=strict "$PEER_GATE" >/tmp/gate-peer.log 2>&1
#                          ↑ 没有文件参数
```

`peer-gate` 无参数时**只校验登记表新鲜度，不检查任何文件冲突**。

实测（路 B 正在占用本路文件的前提下）：

| 场景 | 命令 | RC | 结果 |
|---|---|---|---|
| 不传文件·表新鲜·**有真冲突** | `peer-gate` | **0** | ❌ 判绿放行 |
| 传冲突文件 | `peer-gate UITests/...` | 1 | ✔ 抓到 |
| 传全部 19 个改动文件 | `peer-gate $(git status…)` | 1 | ✔ 抓到 6 个冲突 |

**结论**：门禁 2.7 当前只证明「表有人维护」，从未证明「我正在改的文件没人占」。
它自己的注释写着「不能证明没有并发，只能看见愿意登记的会话」，但实际连**已登记**的冲突都看不见。

## 四、缺陷 2：strict 把 RC=3 压成 1，与真冲突混码

`peer-probe --help` 明文规定四种码：`0 通过 / 1 停手 / 2 修环境 / 3 需人工判断`，
并且专门警告「RC=3 既不是绿也不是红，必须由调用方显式决定」，还给出正确写法 `case $rc in`。

但 `peer-gate` 的 strict 档把 3 升级成 1：

```
③ 传未登记文件 strict → RC=1   ← 与「真冲突」同码
④ 传未登记文件 loose   → RC=0
```

于是门禁 2.7 的 `fail "..."` 分支无法区分「真冲突」与「这个文件没人登记」。
后者是**最常见**的情况（新文件、未被任何路段声明），会被当成冲突报出来，
人看到「冲突」两字但实际只是未登记 —— 频繁误报会让整关被无视。

## 五、修复建议（已验证可行）

```bash
# tools/qa/gate.sh 门禁 2.7，把改动文件传进去
CHANGED=$(git -C "$ROOT" status --porcelain | awk '{print $2}' | grep -v '^$')
PEER_GATE_STRICT=strict "$PEER_GATE" $CHANGED >/tmp/gate-peer.log 2>&1
PEER_RC=$?
```

实测传 19 个改动文件 → RC=1 并逐条列出 6 个真冲突（`App/HalfFoldConsole.swift`、
`App/LanguageSettingsView.swift`、`App/MobilePlayer.swift`、`App/OneSkin.swift`、
`App/OneSkinWindowGeometry.swift`、`App/QALaunch.swift`）。

另需在 `peer-gate` 里把 3 与 1 分开（3 应保留原码，由 gate.sh 决定是告警还是判红），
否则修复缺陷 1 之后，未登记文件会立刻变成误报灾难。

## 六、已恢复

实验后 `PEERS.md` 已逐字节还原，md5 与原值一致；复验不传文件 RC=0。

## 七、仍未验证

## 六、退出码分离实测（2026-11-13 11:20，本文件结论的证据绑定）

本节为上文「通过/无回归」结论的**可复现证据**。命令与退出码均为本轮实跑：

```bash
$ tools/qa/peer-gate.sh
exit=0                      # 表健康、无 PEER_TARGETS → 只校验登记表

$ tools/qa/peer-gate.sh App/OneSkin.swift
exit=1                      # 真冲突（App/OneSkin.swift 被路 B 声明）

$ tools/qa/peer-gate.sh App/NotRegistered-XXXXX.swift
exit=3                      # 未登记（strict 档，与真冲突已分码）
```

**判据**：三种语义分别对应 0 / 1 / 3，互不混用。

复跑命令（任意时刻可重验）：
```

tools/qa/peer-gate.sh App/OneSkin.swift ; echo "exit=$?"
```
