# 右栏偏左 131pt · 根因定位（2026-11-12 16:0x）

## 一、结论先行

**不是布局 bug，是 Fig 虚拟显示器的环境不一致。**

```
vphoned 报的屏幕   : 678 × 466   （真实显示窗口）
App 的 keyWindow   : 951 × 669   （App 认为的窗口）
App 的 proxy       : 951 × 635
```

App 按 **951 宽**排版，实际显示区只有 **678 宽** → 内容被居中塞进 678，
左边界 = `-951/2 = -475.5`（实测 -475），右栏落在 392 而非 523。

## 二、探针证据（全部为本机实测）

```
HSTK  global=-475,-368  size=951x635     ← HStack 宽度正确
PCOL  global=-475  local=0  size=522x635 ← 播放器列
DCOL  global=  47  local=0  size=428x635 ← 详情列
47 - (-475) = 522  ✓ 列分配精确无误
BODYGFX self=951x635 global=-475,-361  avail=951x635  screen=951
```

**三项独立探针一致指向：列宽分配完全正确（522+428=950≈951），
唯一问题是整个 HStack 的 global.minX = -475。**

## 三、-475 的来源（数学闭环）

```
-475 ≈ -951/2 = -475.5
```

⇒ HStack 被「以中心对齐」放入了一个**宽度为 0** 的父容器。
⇒ 因为 App 的 `keyWindow.bounds.width = 951`，而显示器只有 678，
   SwiftUI 把 951 宽的子视图居中到一个它认为「更小」的空间里。

## 四、试过的修复及结果

| 尝试 | 结果 |
|---|---|
| `ZStack` 加 `.frame(width: avail.width)` | ❌ 无效（`avail.width` 本身 = 951） |
| 改成 `.frame(width: min(fixedScreenSize().width, avail.width))` | ❌ 无效（`fixedScreenSize()` 也返回 951） |
| 加 `.clipped()` | ❌ 只裁显示，不改位置 |

**根因是 `fixedScreenSize()` 返回 951 而非 678。**

## 五、这与真机的关系

**真机 Duo 上 `keyWindow.bounds` 与显示区应当一致**（内屏 951×669 就是它自己的显示区），
所以这个偏移**可能只存在于 Fig 这种虚拟单屏环境**。

⚠️ **未验证**：真机当前 `Device State: unavailable`（锁屏），无法确认。
按项目铁律「验收须区分代码路径已验证与真机行为未验证」，此项标记为**环境限制**。

## 六、可做的事

### 选项 A：让 App 认显示区而非 keyWindow（治本）
```swift
// fixedScreenSize() 改为取「真实显示区」
// Fig: vphoned 报 678x466；真机: 应等于内屏
```
但 App 内部拿不到 vphoned 的 678，只能靠 `UIScreen.bounds` / `keyWindow.bounds`，
两者在 Fig 上都报 951 ⇒ **App 侧无法自救**。

### 选项 B：接受 Fig 的坐标系，按 951 归一化比对
既然 App 和真 One 在 Fig 上**都**按 951 排版（真 One 根容器 1331.4 = 951×1.4），
那么**两者其实在同一逻辑坐标系里**，只要正确归一化就能比。

**重新看这段数据**：
```
真 One: 右栏内容 x=523.0，根容器 1331.4（=951×1.4）
我方  : 右栏内容 x=392.0，根容器 1834.0（=951×1.9285）
```
真 One 的 523 是**逻辑坐标**（未缩放），我方的 392 也是逻辑坐标。
**但我方的 HStack 被平移了 -475，所以 392 = 522 - 130？不是。**

`47 - (-475) = 522` ⇒ 我方 DCOL 的逻辑位置是 **522**，不是 392。
**392 是页面内另一个东西**（可能是滚动内容偏移）。

## 七、修正上一节的错误结论

**「右栏偏左 131pt」这个结论错了。** 实际是：
- 我方 **DCOL 逻辑位置 = 522**（真机 523，差 1）✅
- 392 是 `detailColumn` **内部 ScrollView 的内容 x**，受 `pad` 或滚动影响

**⇒ 列位置其实是对的，问题在列的**内部**偏移。**
