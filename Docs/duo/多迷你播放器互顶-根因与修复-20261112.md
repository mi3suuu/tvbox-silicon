# 多迷你播放器「互顶」· 根因、修复与六项审查结果（2026-11-12）

> 用户报告：**第 5 项「迷你播放器可以同时存在多个」没有支持多个，会互顶。**
> 并要求派子代理审查其余 6 项是否完成、有无缺漏。
>
> 排查账本：`rca-dock/rca.md`（19 条假设、逐条判决、reverse check 已通过）。

---

## 一、结论先说：「互顶」是两处结构性错误叠加

### 根因 A · 流资源槽位少于坞上限（画面/流被踢掉）

改前五个容量常量各自硬编码、**互不引用**：

| 资源 | 改前 | 改后 |
|---|---|---|
| 坞里卡片（`VideoTaskCenter.capacity`） | 4 | 4（统一取 `PlaybackCapacity.dock`） |
| 云盘字节流（`CloudStreamStore`） | **3** | 10 |
| 转封装会话（`RemuxStore`） | **3** | 10 |
| DASH 生成清单（`PlaylistStore`） | **4** | 10 |
| 红果解密流（`HongguoStreamStore`） | **4** | 10 |

坞 4 + 前台 1 = **5**，而流只有 **3** 个槽位。逐出策略是 FIFO（`order.removeFirst()`），
逐出动作是 `clear()` / `close()`，**没有回滚、没有重试**。

### 根因 B · 音频会话被任一路的停止动作整锅端掉（声音全没）

`AVAudioSession` 是**进程级单例**。改前 `PlaybackSession.stop()` 无条件
`setActive(false)` —— 停掉坞里任意一路，**其余全部哑掉**；而恢复它们的
`setActive(true)` 只在 `start()` 里跑，所以**不会自愈**。

### 这两个根因共同解释用户看到的三个现象

（RCA 的 reverse check 已逐条核对）

1. **只在坞里 ≥2 个任务时出现** —— 单任务只占 1 个槽位，永远够；
2. **先开的那个坏了、后开的完好** —— FIFO 淘汰最早的那个；
3. **坏掉的不会自愈** —— token/流已从 Store 删掉，`PlaylistLoader` 只会回
   `"This playback has expired. Open the video again."`，必须重新点海报起播。

## 二、第 5 项：改了什么

### 1. 并发预算的唯一真源

`Sources/TVCore/PlaybackCapacity.swift`（新文件）

```swift
public static let dock = 4              // 坞上限
public static let foreground = 1        // 前台那一集
public static let streamsPerTask = 2    // 每路可能要两个槽位（云盘流+转封装；换集时新旧并存）
public static var streamSlots: Int { (dock + foreground) * streamsPerTask }  // = 10
```

四处流存储的上限全部改成读它，**不再有第二个地方能独立调小**。
`Tests/TVCoreTests/PlaybackCapacityTests.swift` 把「坞涨了流必须跟着涨」锁死，
并把旧配置写成可执行反例（`oldCapacitiesWereInsufficient`）。

### 2. 音频会话改成引用计数

`App/PlaybackAudioSession.swift`（新文件）—— 进出各登记一次，只在最后一个参与者
离开时才真的停用。用 `NSHashTable` 弱引用表而非整数计数：某条路径漏了 `leave`
也不会永久泄漏（否则之后**再也停不掉**）。

判定逻辑抽到 `PlaybackAudioSessionPolicy`（TVCore）里以便被测试锁住 ——
「只差一个 if」的错误在代码评审里极难看出来。

### 3. 坞里任务自带作品目录（修自动连播被抢）

`VideoTask` 新增 `catalog` 与 `filesFolder`。改前坞内连播走
`store.nextEpisode(after:)` → `catalog(for:)`，而 `store.playbackCatalog` 是
**Store 上的单值**：坞里再起播第二部剧时 `remember()` 会整个覆盖它。

表现是「坞里只有一个任务时能连播，挂上第二个之后第一个就停住不动」。
这是「互顶」的另一种形态：**不是画面被抢，是功能被抢**。

### 4. 去重键改成「剧+集」

`Channel.id` 含 `url`，同一集换线路 url 就变 → 坞里出现两张其实同一集的卡片。
改为按 `historyContext.id + episodeID` 判，云文件/直播仍按 `Channel` 整体比。

### 5. 修「幽灵卡片」

`settlePlaybackOnLeave()` 的注释写着「只在 watchLayout 真在播时处理」，
**代码里根本没有那个判据**。补上 `guard !store.floatsInMiniPlayer(store.playing)`：
从坞点卡片回到选集页后，若该页因清栈/重压再跑一次 `onDisappear`，
原来会把刚回到前台的那一集**重新塞回坞里**。

### 6. 云文件目录的上下集不再串

`Store.nextFile/previousFile` 增加带 `folder` 参数的版本；`VideoTask` 自带目录。
`Store.file(_:from:in:)` 保留三重比对，拿错目录只会返回 nil，**不会播到别的目录的片子**。

## 三、用户的裁决与据此做的两处行为变更

### 裁决 1：「不止是关音频，而是彻底退出那个视频」

原需求 1（返回→收进迷你播放器）与需求 4（返回→关音频）**字面上互斥**。
用户拍板：**返回/左滑/Back = 收进坞继续播；退出键 = 彻底退出那个视频**。

于是 `exitWatchPage()` 从「停播 + pop」升级为三步：

```swift
let leaving = store.playing          // ① 先记住要退哪一集
leaveHandled = true                  // ② 挡住 onDisappear 自动收坞
store.quitPlayback(leaving)          // ③ 会话收尾 + 从坞里摘掉那一集
dismiss()                            // ④ 离开本页
```

`Store.quitPlayback(_:)` 是新增的，与另外两条路严格分工：

| 动作 | 结果 |
|---|---|
| `dockForeground()`（返回/左滑/Back） | 画面进坞，**继续播** |
| `stopPlaying()`（换集、登出裁决） | 停前台这一路，不动坞里别的 |
| `quitPlayback(_:)`（退出键） | 停 + **从坞里摘掉**这一集，彻底不留 |

缺「从坞里摘掉」这一步的后果：从坞点回来 → 再点退出，那一集会留在坞里继续播，
用户以为退出了其实还在。

### 裁决 2：「这些都做成设置里可选」→ 四档全局 + 逐卡单独设定

`Sources/TVCore/DockAudioPolicy.swift`，设置页在
`App/SettingsPlayback.swift` 的「多任务同时播放的声音」组：

| 档位 | 行为 | 默认 |
|---|---|---|
| `silent` | **全部静音**（画面照常播、进度照走） | |
| `focused` | 只有选中那张出声，其余静音 | ✅ 是 |
| `dimmed` | 选中 100%，其余 15% 背景音 | |
| `mixed` | 全部出声，音量按路数均分（防削波） | |

`silent` 是为「挂着几个任务先放着、但一点声音都不要」准备的——`.focused` 做不到
（它总有一个在响）。

#### 逐卡单独设定（卡片左上角喇叭键）

用户追加要求：「在迷你播放的窗口上可以进行单独小窗的声音设定」。

每张卡片左上角（与暂停键并排）有喇叭键，点开是：

- **静音这一张 / 解除静音** —— 哪怕它是当前选中那张、哪怕全局是「全部出声」；
- **音量滑杆**（0…100%，步进 5%）—— 固定在这一张，不看全局；
- **跟随全局设置** —— 清掉这一张的覆盖，回到跟设置走。

`VideoTask.audioOverride: DockTaskAudio?` 存这个设定。**必须用可选**：
「没设过」与「设成跟随」是两件事——用户没动过这一张时，改全局设置应当立刻生效；
一旦在卡片上动过，就不该被全局覆盖。

优先级统一在纯函数 `DockAudioPolicy.output(isActive:taskIndex:taskCount:override:)`，
**具体压通用，两个方向都成立**（单卡静音压得住「全部出声」，单卡音量也压得住「全部静音」）。
滑杆拖到 0 等同于静音——留一个 `volume == 0 但 isMuted == false` 的状态会让
「是否静音」的判定分叉。单独设过的卡片，喇叭键外圈加一道强调色描边，
让用户看得出「这张被我改过」。

点卡片回到前台时（`take()`）会连同 `isMuted` / `volume` 一起还原：
那是**坞里那张卡片**的设定，不是「这一集永久静音」——用户点回来是要看它，
结果没声音，只会认为播放器坏了。

**诚实边界（已写进设置页说明与代码注释）**：`AVPlayer.volume` 是**播放器级**音量，
不是混音总线。多路能否真的同时输出取决于 `AVAudioSession` 让不让，**必须真机确认**。
若不成立，正确做法是 `AVAudioEngine + MTAudioProcessingTap` 重写音频链路
（见 `多路音频可行性查证-20261112.md`，1~2 周工作量），而不是假装做到了。
**逐卡静音不受这条限制**——`isMuted` 是确定生效的，所以「只想留一张出声、
其余全哑」这种最常见的需求一定做得成。

## 四、子代理审查的六项：4 处真实缺陷，已全部修掉

子代理审出 4 条比我先前核查更严重的问题，**我逐条独立复核后确认属实并修复**：

### 缺陷 1（最高优先）· 需求 2「全局左滑返回」从未生效

`.globalSwipeBack()` 挂在 `RootView` 的 **TabView 外层** `Group.background` 上。
`GlobalSwipeBack.arm()` 首句是 `guard let nav = navigationController else { return }` ——
挂在 TabView 外面的 representable，VC 不在导航栈里，`navigationController` 恒 nil
→ **一条手势都装不上**。

反证：选集页那份 `EdgeSwipeBack` 挂在 `watchBody`（栈内），它拿得到 nav ——
这正好解释「为什么只有选集页左滑像是好的」。

**修**：移到每个分区的 `RouteStack` 内部（每个栈各一份）。

### 缺陷 2 · 即使挂钩对了，慢速拖动也永远不 pop

`handle()` 用 `SwipeBack.isPending`（700ms 时间窗）当「这条手势合法吗」的闸门。
时间窗的语义是「刚刚发生过左滑」，不是「这次手势合法」——
**慢慢拖过半屏、超过 0.7 秒再松手，窗口已过期，页面纹丝不动。**

**修**：改为按手势实例跟踪（`tracking === recognizer`），
并把 `SwipeBack.begin()` 移到 `ended` 分支（只供选集页分流用）。
手势取消时清跟踪且**不**置标记 —— 否则一次半途而废的滑动会让紧随其后的正常返回被误判成左滑。

### 缺陷 3 · 需求 6 在 macOS 上是幽灵播放

`CatalogPosterMenu` 原来只在 tvOS 分支掉，**macOS 走 `#else` 会显示菜单**，
但坞与 `dockForeground()` 全是 `#if os(iOS)`。

→ 点了「Play in Mini Player」= **有声音、无界面、无关闭入口**。

**修**：改为只在 `#if os(iOS)` 挂菜单（macOS/tvOS 不给这个入口）。

### 缺陷 4 · 需求 6 覆盖面严重不足

`OptionalPosterMenu` 全仓只有 `SiteView.swift:113` 一处挂载。订阅源里用户最常
看到海报的 `DiscoveryView` 推荐位**没有菜单**。

**修**：`DiscoveryView` 的 detail 分支挂上 `catalogPosterMenu`
（search 分支没有可播的集，正确不挂）。

### 缺陷 5 · 需求 7 删源后留死卡片

`deleteSite()` 只写 `deletedSources` + `hiddenSources`。
而 `deletedSources` 的消费点只有源列表、搜索、WebCast ——
**收藏与「继续观看」完全不读它**。

→ 删完源后，收藏页与首页「继续观看」各留一张**点一下就报错**的卡片
（`reportMissingFavoriteSource`），且没有批量清理入口 = 实际上删不掉。

**修**：新增 `Favorites.removeAll(fromSource:origin:)` 与
`PlaybackHistory.removeAll(fromSource:origin:)`，`deleteSite` 里按
**origin + sourceKey 两维**清理（单维会误删同域名的其它源或别站的同名 key，
两者都不可逆）。

## 六、没做的 / 必须真机确认

- **`mixed` 档能否真的多路同时出声**：受 `AVAudioSession` 限制，需真机验证。
  若不成立，要么接受「只有一档有效」，要么上 `MTAudioProcessingTap` 重链路。
- **坞内多任务内存**：槽位 3→10，但空槽位不持缓存（`stop()` 会 `clear()`），
  稳态内存应同量级。**需真机开满 4 路跑一段时间看 footprint。**
- **幽灵卡片**：静态补了守卫，但「压页后会不会再消失」取决于运行时栈行为，静态读不出。
- **`PlaybackSession.current`** 仍是单值，但只被 tvOS/macOS 的投屏读取
  （坞只在 iOS），平台不重叠，不影响。

## 七、一句话回归清单（真机）

1. 坞里挂 2 个不同剧 → 都能各自播、切换出声正常、先开的**不黑屏**；
2. 坞里挂满 4 个 → 第 4 个加入后第 1 个**仍在播**（不被逐出）；
3. 长按同一海报两次 → 只有一张卡，且**声音不消失**；
4. 坞里 A（看着）→ 长按海报起播 B → A 进度与声音完好，B 只有画面（静音）；
5. 点 B 卡片 → 回 B 的选集页出声；A 仍在坞里；
6. 从 B 的选集页按返回 → B 回坞，A 仍在（不变两张）；
7. **点退出键 → B 彻底消失**（前台没了、坞里也没了），A 不受影响；
8. 坞里 A 播完最后一集 → 自动连播下一集（不是停住）；
9. 任意被压栈页面（首页/发现详情/源页）**左滑能返回**，且**慢拖也生效**；
10. 设置里切到「其余降到 15%」→ 坞里多张卡片都能听见，非活跃的明显小声；
11. 设置里切到「全部静音」→ 坞里所有卡片都没声音，**画面和进度照常**；
12. 卡片左上角喇叭键 → 点「静音这一张」：即使它是当前选中那张也立刻没声，
    喇叭变成带斜杠，外圈出现强调色描边；点「跟随全局设置」恢复；
13. 卡片喇叭键 → 拖滑杆到 30%：这一张声音明显变小且不再随全局档位变化；
    拖到 0 等同静音；
14. 把某张卡片单独设了静音 → 点它回到选集页 → **有声音**（卡片的设定不跟到前台）；
15. 订阅源推荐位长按海报 → 有「迷你播放器播放 / 下载」两项；
16. 删掉一条源 → 收藏与「继续观看」里它的条目一起消失，并提示清掉了几条。
