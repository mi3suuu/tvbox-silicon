   ```python
   v = unpack('<Q', slot)[0]
   ```

## 5. 结论：上一轮报告错在哪、这一轮应该怎么改

### 5.1 上一轮的诊断方法有系统性缺陷

上一轮 12 个 BUG 的**证据全部来自我们自己的源码 + 截图**，一条也没有对照真机实现。所以：

- **对了的**：小窗误开、方向闸门不解、`UIScreen.main` 量外屏、`suspendAutomaticFloating` 不存在 —— 这些是源码级事实，反不反汇编都成立。
- **错的/漏的**：把「三形态」当成完整空间。真相是**四族 + 半折第五态**；把「小窗」当成 PiP 的一个入口，真相是**小窗是独立的一等服务，PiP 只是它的另一宿主**；把「切屏」当成几何变化，真相是**165 个类实现的显式协议 + 切屏前刷新**。
- **根本方法错**：我们靠 `interfaceOrientation` / size class / 容器宽高比猜形态，哔哩哔哩靠**铰链状态 + 分界线逐帧轮询 + 显式切屏回调**。前者是连续量的间接推断，后者是离散事件 + 稳态收敛。所有「切个形态就错」的 bug 都长在这个差别上。

### 5.2 修复优先级（按「判据类型」而非「症状」排）

1. **补半折第五态**：接 `reservedRegions(kind:.division)` + `onHingeChange`（SDK 27.1 均有，已核），并照 `FramePoller` 的做法写一个「等分界线稳定 N 帧」的轮询器。**没有这一步，任何「形态切换抖动」都只能靠加宽容窗掩盖。**
2. **把小窗升为一等服务**：单独 `MiniScreenState`（尺寸档 + 位置 + 是否用户点过），折叠/展开时**主动重算帧并贴边**（对应 `_foldableUpdateMiniScreenFrame`），不要靠 `DragGesture.onEnded` 的残留 `miniDrag`。
3. **小窗与 PiP 做成同一 mini player 的两个宿主**（照 `pipBiz` / `pipLauncher` / `disablePiP`）：一个数据源、一个播放器，切宿主不改状态。这样 BUG-01/10/11 一起消失。
4. **自动 PiP 加「可失败临时门」**：真写 `suspendAutomaticFloating()`（对 `PictureInPicture` 所有活跃 controller 置 `canStartPictureInPictureAutomaticallyFromInline = false`），在 `duoExpanded` / `orientation` 变化前后各挂一次。对应 `tryDisableAutoPiPAbility`。
5. **切屏改前刷新**：把 `onGeometryChange` 比宽高的被动判据，改成「形态信号变化 → 先刷新（`_refreshBeforeScreenChange`）→ 再重排」的显式协议。
6. 上一轮的 BUG-03（方向闸门）、BUG-06（`UIScreen.main`）、BUG-05/07（写死尺寸）仍然是真 bug，照原顺序修。

### 5.3 三族控件的正确装配方式

不要再写「一个大文件平铺全部控件」。哔哩哔哩的模式是：
```
BBPlayerWidgetConfiguration 声明每族的 Class + Items 清单
→ BBPlayerRootContainerWidget(layoutHalfFoldWithUpperRect:lowerRect:) 负责摆放
→ 各族 Widget 各自只画自己的条
```
我们的 `BiliMetrics` 里已经攒了 60+ 个实测常量，但只有 3 处被引用（`BiliPanels.swift` 2 处、`VideoDetailView.swift` 1 处）—— **常量攒了，装配结构没建**。这是 UI 错绘反复出现的结构性原因。
