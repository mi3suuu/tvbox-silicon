## B. 右栏结构量测脚本

`tools/qa/measure_right_column.py <screenshot.png> [split_x]`

从截图做行级墨迹分析，给出右栏段落数与其 y 起止，用于对照真 One 的 8 段基准。

**scale 判定**（关键，判错则全部数值偏移）：
```
内屏 2007×2853px 按 951×669 逻辑排版 → scale = 2007/951 = 2.110
外屏 1398×2034px 按 466×678 逻辑排版 → scale = 1398/466 = 3.000
判据：先试 951，scale 落在 [1.9,2.3] 就用；否则按 466。
```

修复：QA 强制（`-qaOneShape`）时原样尊重，不按尺寸改判。

# 追加（2026-11-12 18:1x）：形态判定按 One 原始判据重构

## One 的判据（RULES.md §一，已锁定）

```
__pageSize: State<CGSize>     → 横竖 = width > height，一次比较
__division: State<CGRect?>    → 折缝矩形，有=双栏 无=单栏
_wide: LargeCanvas            → 两个 sizeClass，只管大屏/小屏档位，不参与横竖
```

**证据**：`One-1.7.1.interface.swift:1630`（`_wide` 字段）、`:3271`（Body 里只有
`GeometryValueReader<FoldGap?>`，无 LargeCanvas 分支）、`LargeCanvas` 结构只有
两个 `Environment<UserInterfaceSizeClass?>`，**无像素字段**。

## 我方重构前后

| 项 | 重构前 | 重构后 |
|---|---|---|
| 横竖判定 | `ratio >= 1.15` | **`w > h`** |
| 竖持分档 | `w >= 500` | 保留（我方对 Duo 的扩展：外屏 466 / 内屏 669 版式不同） |
| 尺寸源 | `keyWindow.bounds` + `geo.size` + `liveGeometry.box` 三套 | **`geo.size` 唯一** |

## 真实路径验证（不带 QA 强制）


**尺寸源统一已生效**：`proxy` 宽度 669 = `screen` 宽度 669，不再出现 951 的假值。

## 右栏统计行（真机第 4 段）

真机：`1215k 次观看 · 收藏 16k · 评论 237`

我方数据源只有 `Episode.views`，**没有收藏/评论计数**，所以按「只显示真实有的，不编造」：

```swift
let totalViews = episodes.compactMap(\.views).reduce(0, +)
let text = totalViews > 0
    ? "\(compactCount(totalViews)) 次观看 · 共 \(episodes.count) 集"
    : "共 \(episodes.count) 集"
```

`compactCount` 按真机写法用 `k` 不用「万」（真机 `1215k` / `8484k`）。
