## 需求 1 · 不在播放页就显示迷你播放器（未按退出键）

**新规则（本次改）**：只要没点退出键，任何离开方式都进坞。

```swift
// VideoDetailView.swift:3817 settlePlaybackOnLeave()
if leaveHandled { return }              // 只有 exitWatchPage 会置它
guard store.playing != nil else { return }
store.dockForeground()                  // ← 其余一切路径都进坞
```

| 离开方式 | 路径 | 结果 |
|---|---|---|
| 点退出键 | `exitWatchPage()` → `leaveHandled=true` → `stopPlaying()` | 停播 ✅ |
| 左滑手势 | `onDisappear` → `leaveHandled=false` → `dockForeground()` | 进坞 ✅ |
| 导航栏 Back | 同上 | 进坞 ✅ |
| 程序化 dismiss | 同上 | 进坞 ✅ |

**推演结论**：符合「只要不在播放页、没按退出，就展示迷你播放器」。

⚠️ 一个需要留意的点：`SwipeBack.isPending` 现在**不再参与分流**（保留读它只为消警告）。
原先「左滑 = 进坞 / 返回键 = 停播」的分叉已取消，两者统一进坞 —— 这正是新要求。

## 需求 4 · 选集页返回关音频（左滑除外）

⚠️ **与需求 1 的新规则冲突，已按需求 1 覆盖。**

你这次说的「只要没按退出就都进坞」与之前的「返回键关音频」是矛盾的。
按时间顺序，**以最新的需求 1 为准**：返回键也进坞，不再关音频。

**关音频只剩一个入口**：用户点界面上的退出键（`exitWatchPage`）。

| 旧规则（2026-11-11） | 新规则（2026-11-12，本次） |
|---|---|
| 返回键 → 关音频 | 返回键 → **进坞继续播** |
| 左滑 → 进坞 | 左滑 → 进坞（不变） |
| 点小窗键 → 进坞 | 点小窗键 → 进坞（不变） |
| — | **点退出键 → 关音频**（新） |

## 需求 8 · 退出按钮样式/位置（本次重设计）

### 旧版问题
```swift
// 旧：.overlay(alignment: .topTrailing) { 28pt 黑半透明圆 + 白 X }
```
① 与左上角「暂停」同款同尺寸 → 分不清哪个会销毁任务
② 压在视频画面上，亮色内容里 0.5 黑底发灰
③ 多个卡片时找不到
④ 无确认，误触直接销毁

### 新版
```swift
// VideoTasks.swift DockCloseButton
Image(systemName:"xmark").frame(22x22)
  .background(Color.red.opacity(0.92), in: Circle())   // ← 红色，与暂停的黑圆区分
  .frame(32x32)                                        // ← 热区
  .onTapGesture { 抖动提示 }                            // ← 轻点不销毁
  .onLongPressGesture(minimumDuration: 0.45) { action() }  // ← 长按才销毁
// 挂载：.offset(x: 8, y: -8)  ← 卡片右上外沿，不压画面
```

| 旧 | 新 |
|---|---|
| 画面内 topTrailing | **卡片右上外沿**（offset 半出界） |
| 黑色半透明 | **实心红**（破坏性语义） |
| 28pt（与暂停同尺寸） | 视觉 **22pt** / 热区 **32pt** |
| 点击即销毁 | **轻点抖动提示 / 长按才销毁** |

**推演结论**：四项问题逐条对应改掉。

## 冲突与风险清单

### ✅ 已解决的冲突
**需求 1 vs 需求 4**：新规则覆盖旧规则，关音频只剩「点退出键」一条入口。

### ⚠️ 需注意但未改
1. **`miniPlayerActive` 是坞的投影**（`RootView.swift:738` 注释）——
   任何地方写它都会清空**整个**坞。改动坞代码必须用 `videoTasks.start/remove(单个)`。
2. **`SwipeBack` 700ms 时间窗**仍存在，但已不参与需求 1 的分流，
   所以「边缘附近点退出被误判成左滑」这个旧风险**自然消失**（两者现在行为一致）。

### ❓ 需要真机确认的
- 长按 0.45s 的时长是否合适（可能偏长或偏短，需手感验证）
- 红色退出键在深色卡片背景上的对比度
- 多卡片时 8pt 外沿偏移会不会被坞的 `padding(12)` 裁掉
