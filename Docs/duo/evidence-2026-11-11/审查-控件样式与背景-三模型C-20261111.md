## 一、背景层（OneSkinBackdropLayer 全链路）

链路（全部核实）：`refreshBackdrop()`（OneSkin.swift L1429-1464，URLSession 拉海报 → `OneSkinPosterCache` 存 512px）→ `posterImage: UIImage?` → 两处铺层：整页 `OneSkinBackdropLayer(image: posterImage).ignoresSafeArea()`（L1625，stage 根部）+ 窗口内 letterbox 专用 `OneSkinPosterWash`（L2164）。`OneSkinBackdropLayer`（OneSkinBackdrop.swift L72-128）：`Color.black` → `Image(48px downsampled).fill→scale(1.4)→clipped→blur(radius)→opacity(0.6)` → `LinearGradient(top 0.10 → bottom 0.35)` 常驻。

### 缺陷 D1（高）【已验证代码路径 / 需复验像素】—— `.blur` 羽化把整页边缘洗成纯黑，这是内屏 x<30pt 纯黑带的最可能代码路径

- 位置：`OneSkinBackdrop.swift` L88-112，修饰符顺序 `…aspectRatio(.fill) → .scaleEffect(1.4) → .clipped() → .blur(radius: 40) → .opacity(0.6)`。
- 现状：**`clipped()` 在 `blur()` 之前**。SwiftUI 的 `.blur` 是作用在已裁剪结果上的高斯卷积，会在结果四边各羽化约一个半径宽的透明带；羽化区透出 ZStack 底下的 `Color.black`（纯 0,0,0），再乘 `.opacity(0.6)` 后仍近黑。理论羽化带宽 ≈ blurRadius（40pt）× 1–2σ，覆盖 x<30pt 完全吻合。
- 真机：One 的背景外沿没有黑框——顶部 y0-67 亮度 56.3、RGB 暖褐 (69,52,48)→(128,106,98)，色块一直铺到屏幕边。
- 排除项：`pageBase` (0.055,0.047,0.051)=(14,12,13) 不是 (0,0,0)，纯黑不来自它；海报 nil 时是**整页**黑而非仅边缘，与「仅边缘」现象不符。⇒ 最可能就是 blur 羽化，第二候选才是海报加载失败。
- 修复建议：把 `.blur` 移到 `.clipped()` **之前**（blur 大图 → scale 1.4 已把羽化边推到屏幕外 → 再 clip），或 blur 后加 `.frame` 内缩再裁。一行顺序调换即可。
- 需复验：把 blurRadius 设 0 重截内屏竖持，看 x<30pt 黑带是否消失（消失即坐实 D1；不消失再查海报加载）。

### 缺陷 D2（高）【已验证：证据链冲突】—— blurRadius=40 与静态取证直接矛盾，且 669-951pt 大屏上属「二次叠加模糊」

- 位置：`OneSkinBackdrop.swift` L95-108 注释 + `OneWatchPageModel.swift` L126 `defaultBlurRadius = 40`。
- 现状证据冲突：同一份 `OneWatchPageModel` 文档头写明「body 类型链无 `_BlurEffect`、One 背景不存在模糊滤镜」并给出像素复核表（本算法 48px 无 blur：亮度 52.8 / std 11.3 / 边缘 0.56，实机 57.6 / 12.2 / 0.55——**无 blur 已命中**）；同文件 L115-126 又写 Frida dump 见 `gaussianBlur`、按输出反推 radius=40（边缘能量 3.49 vs One 3.41）。两套证据在同一文件里并存且互相矛盾，默认值落在了后一套。
- 等效模糊度算账：48px 源放大到 669pt 宽 = 13.9×（@3x 像素 42×），Lanczos+`.high` 插值本身就是超宽低通，色块已经糊到「没有边界」；再叠 40pt blur = **6% 屏宽**（40/669）的额外高斯，951pt 横屏上 4.2%。反推用的尺度是 263×102 缩图——在那里 40pt blur 只占 ~1.6px，与「无 blur 的 48px 放大」几乎不可分辨，**该匹配是缩图尺度过拟合，不构成大屏上的证据**。真机样本（12/13 号）亮度剖面 56.3/110.7/22.7 与 RGB 暖褐走向，是 48px 放大自然明暗，无需再加 blur 就能由海报产生。
- 修复建议：默认 `blurRadius = 0`（保留用户可调），先用 D1 的顺序修正 + 48px 放大跑一轮真机对照；若真机观感仍差再小步上调（12–16pt 量级），不要 40。
- 需复验：blur=0 与 blur=40 两版各截一张内屏，与 One 12/13 号做亮度剖面/边缘能量对比。

### 缺陷 D3（高）【已验证】—— 标签胶囊与 One 差一个量级：高度 20 vs 29.667、等宽结构缺失、行距 7 vs 14.333

- 位置：`OneSkin.swift` tagFlow（L2574-2590）。
- 现状 vs 真机偏差表：

## 四、「明暗由海报决定」原则自洽性核验【已验证】

1. 渐变 0.10/0.35：`topDim/bottomDim` 已在 `OneWatchPage.Backdrop`（真值源）与 `OneSkinBackdropMetrics` 两处同步改定，注释完整记录了反推（0.88 → 需 L315 物理不可能）。最终亮度公式：top = 0.6×0.9 = 0.54 海报贡献、bottom = 0.6×0.65 = 0.39 —— 对照真机 top 56.3/最亮 110.7/底 22.7，要求海报亮度 L≈104/L≈205/L≈58，全部落在 0–255 物理可行域内。**自洽**。
2. 渐变是否只在有海报时叠加：渐变**常驻**（不在 `if let` 内），与 One 二进制 ZStack 第三个元素常驻的取证一致；`image==nil` 时 = 黑底+渐变，无断层。**正确**。
3. 渐变方向 `.top→.bottom` 两停，无第三停、无取色（`getHue/CIAreaAverage` 全链路 0 引用）。**符合**。
4. 遗留提醒：0.10/0.35 是「人为修正」而非二进制原值（0.15/0.88），代码注释已写明，但 `OneWatchPageModel` 文档头 §一 的类型链伪代码里仍印着旧值 0.15/0.88（L51-53 注释块），新读者容易被文档头带偏 —— 属文档不一致，非代码缺陷。

## 五、确认无误清单（代码路径已验证）

1. 背景三常量 maxPixel=48 / scale=1.4 / coverOpacity=0.6 全部转发自 `OneWatchPage.Backdrop` 单一真源，无散落字面量。
2. ImageIO 降采样实现逐行对照 One `sub_10011c554`：`CreateThumbnailFromImageAlways` 无条件缩、多帧原样返回、EXIF 方向、NSCache(countLimit 8)。
3. 渐变常驻层方向/两停与 One 一致，无海报时不断层。
4. chip 本体（倍速/循环/填充/线路）实现与 One 实测一致：**无底、无描边**，开启态蓝字 #1A6CC7 + 深蓝底 #000D1C（仅 accent 项），与真机 #131315 底/#F7F7F9 字吻合。
5. 继续播放白底黑字方向正确（One 外屏实测亮白胶囊）。
6. `pageBase #0E0C0D`、`primary #F8F8F8` 与 One 实测吻合。
7. 背景整页铺一层（stage 根部）而非画面列局部，无「底部渐隐白层」回归路径（DetailAurora 仅 macOS）。
8. blurRadius 用户可调管道（UserDefaults 键、0=关、0–80 范围）存在且键名稳定。
9. OneSkin 全链路无 `glassEffect` 调用（glassEffect 仅 GlassKit，OneSkin 未用）——与「胶囊是纯色半透明」的现状一致，问题在材质选择而非意外混入。

## 七、Top3（按视觉影响排序）

1. **D1 blur 羽化露黑**——整页四边 30–40pt 纯黑框，是内屏截图「边缘全黑」的第一嫌疑，一行修饰符顺序可修，视觉权重最大。
