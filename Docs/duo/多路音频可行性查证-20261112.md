# iOS 多视频同时出声 · 可行性查证

**方法：读本机 Xcode SDK 官方头文件（`iPhoneOS27.2.sdk`），不是凭记忆或猜。**

## 一、直接结论

**iOS 上「同一个 App 里多个 AVPlayer 同时出声」是做不到的 —— 系统层面就不允许。**

原因在 `AVAudioSession`：它是一个**进程级单例**，整个 App 只有一个 session。
多个 `AVPlayer` 实例共享它，所以同一时刻只有一个能真正输出到扬声器。
后起播的那个会「抢」session，之前的被系统静音或暂停。

## 二、逐条证据（SDK 头文件原文）

### 1. `AVAudioSessionCategoryMultiRoute` 不是我们要的东西

```objc
// AVAudioSessionTypes.h
/*! Use this category to customize the usage of available audio accessories
    and built-in audio hardware. For example, this category provides an
    application with the ability to use an available USB output
    and headphone output simultaneously for separate, distinct streams
    of audio data. */
AVAudioSessionCategoryMultiRoute API_AVAILABLE(ios(6.0))
```

**它是「把不同流送到不同输出设备」（USB 一个、耳机一个），不是「同一设备混音」。**
接普通扬声器时，`BuiltInSpeaker` 甚至被明确限定「只允许在没有其它输出时使用」：

```
Note that AVAudioSessionPortBuiltInSpeaker is only allowed to be used
when there are no other eligible outputs connected.
```

⇒ **MultiRoute 对「坞里几个视频同时出声」没有帮助。**

### 2. `AVAudioSessionCategoryOptionMixWithOthers` 也不是

```objc
/// MixWithOthers is only valid with AVAudioSessionCategoryPlayAndRecord,
/// AVAudioSessionCategoryPlayback, and AVAudioSessionCategoryMultiRoute
AVAudioSessionCategoryOptionMixWithOthers = 0x1,
```

**它是「和别的 App 混音」（比如让音乐 App 不被打断），不是「本 App 内部混自己的多路」。**

### 3. 唯一能同设备混音的是 `AVAudioEngine`

```objc
// AVAudioEngine.h
@property (readonly, nonatomic) AVAudioMixerNode *mainMixerNode;
```

`AVAudioEngine` + `mainMixerNode` **可以**把多个 `AVAudioPlayerNode` 混到一路输出。
但代价是：**必须把音频从 `AVPlayer` 里取出来**——

```objc
// AVPlayerItem.h
@property (nonatomic, copy, nullable) AVAudioMix *audioMix;
// Audio media will be mixed according to the parameters provided via
// AVPlayerItem.audioMix, if present.
```

配合 `MTAudioProcessingTap`（`MediaToolbox`，iOS 6+）才能把每路 `AVPlayer` 的
PCM 抽出来喂进 `AVAudioEngine`。

## 三、三条可行路线（按代价排序）

### A. 现状：只有一个出声（已实现，推荐保留）
```swift
// VideoTasks.swift:162
for task in tasks { task.session.player.isMuted = task.id != activeTaskID }
```
- 代价：0
- 体验：坞里多个视频都显示画面，**只有选中的那个出声**，其余静音
- 这是**行业通行做法**（YouTube / Safari 多标签也是这个行为）

### B. 全部混音（AVAudioEngine + MTAudioProcessingTap）
- 代价：**高**。要给每路视频挂 tap、抽 PCM、维护 N 个 `AVAudioPlayerNode`、
  处理采样率不一致、重新实现音量/淡入淡出/音频轨道切换
- 风险：`AVPlayer` 自带的无缝切换、音画同步、HLS 自适应都会受影响
- **而且体验上多半是灾难**：3 个视频同时说话，用户听不清任何一个

### C. 折中：允许「同时播但自动压音」
- 主任务 100% 音量，其余降到 10~20%（`player.volume = 0.15`）
- 视觉上「都在播」，听觉上以一个为主
- 代价：**很低**（改一个 `volume` 值），不需要 AVAudioEngine

## 四、建议

**保留 A（现状），如果确实要「都在播」的感觉，加 C 的低音量档。**

理由：
1. A 已是 7 项需求里「多任务随时切回」的正确实现 —— 用户要的是「随时选择回到哪一个」，
   不是「同时听多个」
2. B 的工程量和回归风险极大（要重写整条音频链路），且体验上反人性
3. C 是唯一「低成本 + 有感知」的中间档

**需要你拍板**：是保留 A，还是加 C（非活跃降到 15% 音量）？

## 五、如果坚持 B 的落地顺序（不建议，但记录）

1. `AVAudioEngine` 单例 + `mainMixerNode`
2. 每路 `AVPlayerItem.audioMix = AVMutableAudioMix(items: [tap])`
3. `MTAudioProcessingTapCreate` 回调里把 PCM 写进对应 `AVAudioPlayerNode`
4. `player.isMuted = true` 关掉 `AVPlayer` 自己的输出，只留 tap 通路
5. 处理：采样率转换、时钟同步、seek 时的 tap 重建、HLS 不连续段的处理

**这是 1-2 周的工作量，且有大量边角。**
