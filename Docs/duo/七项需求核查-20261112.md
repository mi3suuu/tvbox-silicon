## 需求 6 的实现细节（它做得比要求更细）

```swift
// VideoTasks.swift:442
content.contextMenu {
    Button { Task { await store.videoTasks.start(video: video, client: client, store: store) } }
        label: { Label(L10n.text("Play in Mini Player"), systemImage: "rectangle.inset.bottomright.filled") }
    Button { Task { await prepareDownload() } }
        label: { Label(L10n.text("Download"), systemImage: "arrow.down.circle") }
}
```

- **不影响已有坞任务**：走 `store.videoTasks.start(...)`（新增一个 task），不碰 `miniPlayerActive`
- **索引源不挂菜单**：`OptionalPosterMenu(enabled: !isIndex)` —— ranking/列表站的海报点了是跨源搜索，没有可播的一集
- **用空修饰器保持视图身份**：注释说明「不能写成 if/else 包住整段，那样两个分支是不同视图身份，滚出屏幕的卡片重建时会丢掉 onAppear 的续页触发」
- **tvOS 不挂**：系统无 contextMenu，遥控器长按不可靠

## 两个实现里已自认的风险（不是缺陷，但要知道）

### 1. `SwipeBack` 700ms 时间窗
```swift
// VideoTasks.swift:293
static func begin() { pendingUntil = Date().addingTimeInterval(0.7) }
```
在屏幕左缘附近点退出会被当成左滑。
**已缓解**：`exitWatchPage()` 先置 `leaveHandled = true`，`onDisappear` 看到就不再读时间窗。

⚠️ **只覆盖「点退出键」这一条路径。** 硬件返回键 / 系统手势竞争等其他路径若依赖
`SwipeBack.isPending`，仍可能误判。代码注释自己也写明了这一点。

### 2. `miniPlayerActive` 是「坞的投影」，不是单任务开关
```swift
// RootView.swift:738
// ⚠️ `miniPlayerActive = false` 现在是「清空**整个**坞」
```
任何地方误写它都会清空所有任务。改坞相关代码时必须用 `videoTasks.start/stop(单个)`，
不能用这个全局量。
