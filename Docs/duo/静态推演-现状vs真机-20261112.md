**方法**：纯代码推演 + 截图文件命名语义对照。**不用 AX、不用日志、不截图分析。**

素材：桌面 16 张真机截图（用户已重命名，语义明确）

| 形态 | 状态 | 张数 | 画布 |
|---|---|---|---|
| 外屏 | 未播放 / 暂停播放 / 选集 | 4 | 466×678 |
| 展开横屏双栏 | 未播放 / 暂停播放中 / 选集 / 选线路 / 选触发按钮 | 5 | 669×951 存储（逻辑 951×669） |
| 展开竖屏 | 未播放 / 暂停播放 / 选集 / 选线路 | 4 | 669×951 |
| 竖屏(合盖) | 暂停播放 / 暂停播放2 / 选线路 | 3 | 669×951 |

## 一、我方代码的四条布局分支

```
OneSkin.swift:1879  fullScreenNow              → 全屏（横/竖两态）
OneSkin.swift:1927  effectiveShape == .fullBleed → 展开宽屏（竖持）
OneSkin.swift:1949  landscapeNow               → 横持双列
OneSkin.swift:2026  else                       → 竖屏单列
```

**真机截图的形态种类**（外屏 / 展开横屏 / 展开竖屏 / 合盖竖屏 / 各自 × 播放态）
→ **远多于我方四条分支能表达的组合**。

## 二、右栏结构差异（内屏展开横持，最严重）

### 真 One 实测结构（8 段）

```
1. 标题      y=38.0   w=317.3  h=54.3
2. 副标题    y=100.3  w=316.7  h=38.0   「第 1 集 · 日期」
3. 元信息    y=146.3  w=182.3  h=14.3   「2026-11-03 · 作者」
4. 统计      y=168.6  w=188.0  h=14.3   「1215k 次观看 · 收藏 16k」
5. 继续播放  y=205.0  w=168.0  h=52.0   ← 主行动按钮
6. 标签行1   y=279.0             h=44     ← 3 个 chip
7. 标签行2   y=323.0             h=44     ← 3 个 chip
8. 说明      y=389.0  w=327.7  h=58.0
```

### 我方 detailColumn 代码顺序

```
1. Color.clear spacer h=38
2. Text(shown.name)            标题
3. Text(metaTop.joined)        元信息
4. Text("共 N 集")
5. Text(lineLabel)             线路
6. Text(synopsisText)          简介
7. Button 合集·共N集
8. ForEach episodes            选集卡片
9. Button 下载
10. Text 评论 / commentPreview
```

### 逐项判定

| 项 | 真 One | 我方 | 判定 |
|---|---|---|---|
| 副标题行（第N集·日期）| 有，h=38 | **无** | ❌ 缺整行 |
| 统计行（观看/收藏/评论）| 有，h=14.3 | **无** | ❌ 缺 |
| 继续播放按钮 | 有，168×52，主行动 | **无独立按钮** | ❌ 缺主行动 |
| 标签行 | 两行 × 3 chip，h=44 | 只有一行 `Text(lineLabel)` | ❌ 结构不同 |
| 选集位置 | 标签行之后 | 简介之后（更靠上） | ⚠ 顺序不同 |
| 说明 | y=389（末段）| 第 6 位 | ⚠ 顺序不同 |

**结论：我方右栏不是「位置偏几 pt」，是少了 3 个结构块（副标题/统计/继续播放）+ 标签行结构完全不同。**

这解释了为什么真机右栏看起来"满"，我方看起来"空"。

## 三、形态覆盖差异

真机截图里明确出现的状态组合：

```
外屏:        未播放 / 暂停播放 / 选集
展开横屏双栏: 未播放 / 暂停播放 / 选集 / 选线路 / 选触发按钮
展开竖屏:    未播放 / 暂停播放 / 选集 / 选线路
合盖竖屏:    暂停播放 / 选线路
```

我方布局分支只有 4 条，**每条分支内部的「未播放 / 暂停播放」差异靠 `playing` 参数在内容层区分，但结构（有几段、什么顺序）不随播放态变化**。

**而真机截图的命名显示：播放态变化时，右栏结构会变**（例如「未播放」vs「暂停播放中」是两张不同截图）。

## 四、可确证 vs 需核实

### 可确证（纯代码）
1. 我方右栏缺 3 个结构块（副标题、统计、继续播放）
2. 我方标签是纯文本，One 是 chip 行
3. 我方选集在简介之后，One 在标签行之后
4. `availableSize` 有方向/尺寸不同源的塌缩缺陷（已修）

### 需核实（代码推不出）
1. 真机「未播放 vs 暂停播放」时右栏具体差什么（命名只说状态不同，没说差什么）
2. 外屏 466×678 的右栏结构（没有 AX 数据）
3. chip 的具体尺寸与间距

## 五、下一步建议

**优先级 1：补齐右栏 3 个缺失结构块**
- 副标题行（`第 N 集 · 日期`，h=38）
- 统计行（`xxx 次观看 · 收藏 xx · 评论 xx`，h=14.3）
- 继续播放按钮（168×52）

**优先级 2：标签行从 Text 改成 chip 行（每行最多 3 个，h=44）**

**优先级 3：调整顺序为 标题→副标题→元信息→统计→继续播放→标签→说明→选集**

这三项都是**纯结构改动，不涉及坐标微调**，改完我方右栏才和真机"看起来是同一个界面"。
