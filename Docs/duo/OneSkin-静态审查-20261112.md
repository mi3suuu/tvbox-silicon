## 一、确证缺陷（有代码证据）

### D1 · HIGH · 死代码：两个零引用类型
```
OneSkinCanvasWidth   0 处引用（Sources/TVCore/OneSkinStageSize.swift:111）
OneSkinKeys          0 处引用（Sources/TVCore/OneSkinShared.swift:13）
```
**影响**：`OneSkinCanvasWidth` 里如果是「宽屏判据」的实现，说明判据写了两份、只用了一份。
**建议**：删除或接线，不可保留两套判据。

### D2 · HIGH · 两套尺寸基准并存
```
OneSkin.fixedScreenSize()          App/OneSkin.swift:94   读 keyWindow.bounds
OneSkin.availableScreenSize(_:)    App/OneSkin.swift:161  读 scene.screen.bounds
```
两者都返回「屏尺寸」，但一个读 keyWindow、一个读 screen，**在窗口化环境下会给出不同值**。
**影响**：`box`（可用区）与 `ratioBase`（比例基准）可能来自不同源 → 所有比例坐标偏移。
**建议**：`availableScreenSize()` 改为调用 `fixedScreenSize()`，消除第二源。

### D3 · MEDIUM · 常量命名与语义相反
```
Metrics.columnLeft  = 0.4501  → 实际用作「详情列宽」  (OneSkin.swift:1918)
Metrics.columnRight = 0.4918  → 实际用作「播放器列」  (OneSkin.swift:1983,1993)
```
Core 里注释已承认「命名当初按倒立帧写反了」，但**没改名，只在使用处做了语义对调**。
**影响**：任何新代码按名字取值都会取反 → 右栏/左栏互换（这正是我们今天反复踩的坑）。
**建议**：重命名为 `detailColumnWidth` / `playerColumnWidth`，一步消掉。

### D4 · MEDIUM · 相同算式重复两处
```swift
// OneSkin.swift:1983-1984 与 1993  完全相同的 barW 计算
max(min(ratio.width * Metrics.columnRight - ratio.width * 0.10,
        ratio.width * Metrics.columnRight), 240)
```
一处是实际赋值、一处是 DEBUG 日志重算。
**影响**：改一处忘另一处 → 日志与实际不符（我们今天已被误导过一次）。
**建议**：抽局部常量，日志直接引用。

### D5 · MEDIUM · OneSkinStage 单视图 30 个 @State
```
@State isScrubbing / dragProgress / showsSpeedMenu / showsLineMenu /
       controlsCollapsed / showsQualityMenu / showsAudioMenu /
       lineLatency / lineLatencies / pip / tracks / probingLines / ...
```
**影响**：任一状态变化都让 3319 行 body 重算。这是「控件推移」的结构性温床——
即使几何算对了，高频状态也会带动整页重排。
**建议**：把菜单开合类状态下沉到子视图（`OneSkinPlayerChrome` 已有独立结构，
可直接搬过去），`OneSkinStage` 只保留几何相关状态。

### D6 · LOW · landscape 判定分散 4 处
```
oneSkinShape      VideoDetailView.swift:1998   ← 唯一判定入口
shape             OneSkin.swift:795            ← 参数
shapeNow          OneSkin.swift:985            ← @State 镜像（已证实滞后一帧）
effectiveShape    OneSkin.swift:1067           ← 最终消费者
```

`shapeNow` 实测出现 `mirror=LAG`（4 次），是振荡驱动源之一。
**建议**：删除 `shapeNow`，`effectiveShape` 直接返回 `shape` 参数（当前已是这样，但 `shapeNow` 仍在别处被读）。
